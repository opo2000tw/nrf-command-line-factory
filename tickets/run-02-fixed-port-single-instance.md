## 背景
當使用 `-addr` 指定固定埠且該埠已被佔用（例如程式已經在跑）時，`net.Listen` 失敗會直接觸發 `log.Fatal`，訊息對現場人員不夠友善，也可能造成重複啟動的困惑。

## 驗收條件
- [ ] 埠被佔用時顯示明確訊息（例如提示可能已在執行中、請關閉舊視窗），而不是丟出 fatal stack trace
- [ ] 選配：偵測既有實例後改為開啟既有的 URL，或明確拒絕啟動並說明原因
- [ ] 不影響預設的隨機埠啟動行為
